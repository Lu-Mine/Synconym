# Synconym 设计方案

> 两个人（或四个人）各自写一个词，同时揭晓，从上一轮的词继续靠近，直到想到同一个东西。
> 判定交给玩家投票，身份交给 uid。

## 一、入口

1. **创建房间** —— 选模式与设置，进等待大厅
2. **按房间号加入** —— 输入 5 位数字房号
3. **邀请链接直达** —— `/?r=CODE` 打开即进房

## 二、房间设置

| 设置项 | 取值 | 默认 | 控件 |
|---|---|---|---|
| 轮次上限 | **4–20 任意整数** | 12 | 步进器 `−  12  +` |
| 写词时限 | 15 / 30 / 45 / 60 秒 | 45 | 分段选择 |
| 准备时限 | 15 / 30 / 45 / 60 秒 | 30 | 分段选择 |
| 禁止重复词 | 开 / 关 | 开 | 开关 |
| 模式 | 自由 / 主题 | 自由 | 分段选择 |

- 投票倒计时固定 5 秒，不设开关
- 主题模式不选具体主题：开局由服务端从 20 个主题中随机抽取一个并锁定整局，详见 §6.4
- 房间支持 **2–4 人**，不设"期望人数"，全凭房主何时按开始
- 房主在创建时设定，等待大厅内仍可修改，开局后锁定

## 三、等待大厅

- 房号 5 位纯数字，创建即显示，可一键复制邀请链接
- 玩家点「准备」，状态实时同步
- **非房主全员准备且在线后，房主的「开始」按钮才可用**；房主固定显示「房主」标签，无需准备，点击才真正开局
- 准备期间可做的事：
  1. 查看房间设置（房主可改；非房主只显示取值文本，不出现任何控件，条目行高与房主视图一致。轮次上限与两个时限带四档强度条，段位对应分段选择器的四档，轮次按 4–7 / 8–11 / 12–15 / 16–20 归段；开关类选项显示绿勾开启 / 红叉关闭；主题模式只显示「开始后随机抽取主题」的说明）
  2. 查看并复制房号与邀请链接
  3. 改自己的名字
  4. 邀请其他人
  5. 准备 / 取消准备
  6. 房主点击其他在线玩家转让房主（弹窗二次确认，转让后原房主变普通玩家需准备）
  7. 退出房间
- 准备状态在等待大厅内可随时切换，没有冷却窗口；准备阶段（轮间）由服务端校验是否允许准备

## 四、一局的流程

### 4.1 状态机

```
lobby ──非房主全员准备且房主点开始──▶ writing
writing ──全员提交/超时──▶ 判定
                            ├─ 全部写同一个词 ─────────▶ result（成功）
                            └─ 否则 → voting（固定 5s）
                                        ├─ 全票通过 ───▶ result（成功）
                                        └─ 未通过 → 弹窗 → prepare / breakVote
prepare / breakVote ──▶ 下一轮 writing（或 result）
游玩中只剩 1 人（其余退出或断线过期）──▶ interrupted（不入库，只能回房间或回主页）
```

### 4.2 写词（writing）

- 所有人同时写，互不可见；输入实时节流上报，用于显示"正在输入"
- 实时显示每人状态：**已提交 / 正在输入 / 未开始**
- **输入阶段由前端先过滤**：允许汉字、字母、数字和空格；标点、emoji 不接受；超过 12 字的内容自动裁掉。
- **提交阶段由服务端拦下所有不合法内容**：不符合字符、长度或重复词规则时拒收并说明原因，不消耗本轮，玩家可以继续改
- 倒计时结束时，**输入框里的内容就是答案**，由服务端当作提交处理，走同一套校验，因此超时也可能相遇
- 答案格最终只有三种形态：空 → `[未提交]`；非空但不合法 → `[非法答案]`；合法 → 原文
- 不合法内容不参与判定

### 4.3 判定与投票

- **全员写出同一个词（归一化后比较）→ 直接判赢**，跳过投票
- 否则进入投票，固定 5 秒，同屏展示本轮所有词，下方是「是」/「否」
- 同时投、同时揭晓，投票期间看不到任何人的选择
- 全票「是」→ 相遇；任一人「否」或超时（算否）→ 未通过
- 顶部小弹窗提示「全票通过」/「未通过」，然后过渡到结算页或下一阶段

### 4.4 准备（prepare）

- 每轮未相遇后进入，倒计时为准备时限
- 全员准备 → 立即进下一轮；倒计时结束 → 无论准备与否直接进下一轮
- 若进入准备阶段时仍有保留席位的掉线玩家，当前准备时限在原配置基础上增加 10 秒（多人不叠加、主动退出不触发）。前 10 秒时钟图标和秒数显示蓝色，提示「有人掉线，多等一会」；该等待期不可被全员准备跳过。10 秒结束后恢复原准备规则，已全员准备则自动下一轮；重新掉线或重连不延长本次时限。
- `prepareGraceDeadline` 下发额外等待截止时间，前端按服务器时间局部更新颜色和提示，不重建页面。

### 4.5 崩局投票（breakVote）

- **仅当轮次上限 ≥ 8 时才存在**
- 触发点：**每满 5 轮**且未到终点 —— `round % 5 === 0 && maxRounds >= 8 && round < maxRounds`

  | 轮次上限 | 触发轮 |
  |---|---|
  | 4 / 5 / 6 / 7 | 无 |
  | 8 | 第 5 轮后 |
  | 12 | 第 5、10 轮后 |
  | 16 | 第 5、10、15 轮后 |
  | 20 | 第 5、10、15 轮后 |

- 该轮的准备阶段被替换为二选一：「下一轮」/「玩崩了」，倒计时用准备时限
- **达到或超过半数选「玩崩了」→ 失败页，本局记录直接丢弃**
- 未达半数 → 直接进入下一轮，不再走一遍准备
- 当已有票数使结果不再受剩余选票影响时立即计票；掉线保留席位及已投选择，未投票席位在截止前仍可能投票。
- 崩局阶段以警示配色区别于其他阶段；选择「玩崩了」需要二次确认，明确提示对局可能结束且记录不保存。

### 4.6 结束路径

| 路径 | 页面 | 是否落库 |
|---|---|---|
| 精确相遇 | 成功 | 是 |
| 投票全票通过 | 成功 | 是 |
| 打满轮次仍未相遇 | 失败 | 是 |
| 崩局投票通过 | 失败 | **否，丢弃** |
| 游玩中只剩 1 人（其余退出或断线过期） | 中断（`interrupted`） | **否，丢弃** |

中断页只提供「回房间」与「回主页」；回房间重建等待页并重置准备，本局词路径不再展示。

## 五、结算页

- 内容：完整词路径（原文 + 每格标记 `[未提交]` / `[非法答案]`）、投票记录、第几轮相遇
- 导出：完整词路径标题行箭头左侧的「导出结算海报」把品牌标识、对局概览（参与者、轮次、模式，主题模式下另带主题）和完整词过程渲染成 PNG 下载，**不含房号**；文件名只用导出时间，版式要求见 §10.6
- 出口：
  1. **重赛** —— 全体有效玩家选择重赛且至少 2 人，按原配置直接开始下一局，不经过等待页。
  2. **回房间** —— 留在原房间等待页，可调整配置；若有人选择此项，待全员选择完成后统一回等待页，不自动开局。
  3. **回主页** —— 仅退出本人，不关闭其他玩家的房间。
  进入结算立即开始 **30 秒**计时。截止先移除未选择及仍离线者；剩余至少 2 人且全部选重赛则同配置直接开局，有回房间选择或仅 1 人则回等待页，无人留下才销毁。

### 5.1 退出、加入与重连提示

- 顶部小弹窗统一使用服务端下发的 `toast` 消息，沿用 §10.3 的 Toast 动效（顶部滑入，2.5 秒后滑出）。
- 玩家在**房间准备页、游玩过程、结算页主动退出**时，向仍在房间内的其他玩家提示「XXX 已主动退出房间」；退出者本人回首页，不再收到该房间消息。
- 玩家在**房间准备页加入**时，向房间内已有玩家提示「XXX 加入了房间」；加入者也收到同一事件的提示。
- 掉线时提示「XXX 连接已断开，席位暂时保留，等待重连」，有效窗口内恢复后提示「XXX 已重新连接，回来了」；断线窗口过期移除时提示「XXX 重连已超时，席位已移除」；结算窗口到期未选择者提示「超时未选择已退出」。各事件只广播一次。
- 提示是旁路事件，不改变全量 `state` 快照和服务端权威状态；同一事件只广播一次。

### 5.2 全局主动退出与断线恢复

- **主动退出**（退出按钮、回主页确认、主动切换房间）：所有阶段立即移除席位及参与资格，不保留 90 秒回归机会、不自动带回房间；只有房间尚处等待页时可手动作为新席位加入。
- **网络断线 / 刷新 / 关闭标签页**：大厅与游玩阶段保留原 UID、座位及同阶段已提交词/投票 90 秒，可在窗口内恢复；不是主动退出。游戏不暂停，离线者不参与提交完成、投票统计及准备完成判断。
- 恢复从服务端当前阶段继续，不补发错过的答案或投票，不重放客户端旧阶段的操作；跨阶段按当前状态操作。
- 结算与重赛阶段改用本局结算的固定 30 秒截止时间，不另起 90 秒，详情见 §5.3。
- 主动退出者不会恢复到已开始本局，但 `matchPlayers`、完整词路径及已保存对局仍保留其历史记录。
- 客户端断线时显示重连提示并暂停操作，收到权威状态后恢复；主动退出意图优先于重连，若发送退出时断线则在恢复连接后完成退出。同 UID 被另一页面接管时，旧页面停止自动重连。

### 5.3 再来一局投票中的退出者（已实现）

- 进入结算时初始化有效玩家 UID 集合 `rematchEligibleUids` 与固定 30 秒截止时间，不等待任何玩家点击，不因选择或重连延期。
- `rematchVotes` 记录 `'rematch' | 'room'`，等待中允许改选。主动退出立即删除资格和选择；断线保留资格及原选择，等待截止前重连。
- 截止前只有全部有效玩家在线且完成选择才提前分流：至少 2 人全重赛直接开局；有人回房间或仅 1 人则回等待页。断线者阻塞提前分流。
- 30 秒到期先移除未选择或仍离线者，再对剩余玩家应用相同分流规则；迟到消息或重连不能挽救已被移除的资格、不能污染新局。
- 回主页不关闭他人房间，有效集合为空才销毁。回等待页或直接开局时清除上一局临时状态并重置准备；完整结算记录仍保留在数据库。

## 六、判定细则

### 6.1 归一化（比较前执行）

```
norm(w):
  1. Unicode NFC
  2. 全角 → 半角
  3. 繁体 → 简体
  4. 移除所有空格（含盘古空格）
  5. 字母转小写
  6. 去首尾空白
```

两个词 `norm` 后严格相等才算"同一个词"。展示时永远保留玩家原文。

- **盘古空格**：`iOS 手机` 与 `iOS手机`、`New York` 与 `NewYork` 视为同一个词
- **繁简**：`憂鬱` 与 `忧郁`、`臺灣` 与 `台湾` 视为同一个词
- 实现：服务端用 `opencc-js`（t2s）做繁简转换，其余为正则

### 6.2 词的约束

- 长度 **1–12 个字符**（按归一化后计数）
- 允许汉字、字母与数字，不允许标点、emoji。
- 空格允许，但比较时忽略
- **长度与字符类在前端输入时就拦死**：打不进去、粘不进来，超出部分直接裁掉

### 6.3 禁止重复词（房间选项，默认开）

- 开启时：本局出现过的词不可再次提交（含自己用过的）
- 服务端在提交时拦截并提示「这个词本局用过了」，不消耗本轮，可继续改
- 关闭时：允许任意重复

### 6.4 主题模式（可选，默认关闭）

主题模式在每局开始时由服务端从以下 20 个主题中随机抽取一个，向所有玩家公布并锁定整局；重赛重新抽取，允许与上一局相同。回大厅后不提前抽取。

主题是联想的共同范围，不设置禁词或答案白名单，也不自动判定答案是否属于主题，由玩家自行遵守。其他词语校验规则不变。

| 主题 | 主题 | 主题 | 主题 |
|---|---|---|---|
| 王者荣耀 | B站UP主 | 欧美音乐 | 国语音乐 |
| 春节 | 火锅 | 高铁出行 | 校园 |
| 故宫 | 熊猫 | 海洋 | 天气预报 |
| 短视频 | 网购 | 手机 | 装修 |
| 露营 | 咖啡 | 传统中医 | 宠物 |

实现：主题表在 `data/themes.json`（20 个稳定 ID 与展示名）。服务端在开局共同入口 `selectTheme` 抽一次并写入房间状态，随后随全量快照下发 `themeId` / `themeName`；重赛重新抽取，回大厅或切到自由模式时清空。结算把 `mode` 与 `theme_id` 写入 `matches`，自由模式为 `null`。客户端提交的主题字段一律忽略。

## 八、数据结构

### 8.1 服务端内存（房间）

```ts
type Phase =
  | 'lobby' | 'writing' | 'voting' | 'prepare' | 'breakVote'
  | 'result' | 'rematch' | 'interrupted'

interface Player {
  uid: string
  name: string
  seat: number                 // 0..3，决定配色
  connected: boolean
  ready: boolean
  draft: string                // 输入框内容，超时即作为提交
  submittedWord?: string       // 不广播
  vote?: boolean               // 不广播
  breakVote?: boolean          // 不广播
  joinedAt: number             // 排序与房主移交依据
  disconnectedAt?: number
  leftReason?: 'disconnect'
}

interface RoundRecord {
  n: number
  words: Record<string, string>    // 展示用原文
  marks: Record<string, 'none' | 'empty' | 'invalid'>
  votes?: Record<string, boolean>  // 投票结束后的逐人选择
  outcome: 'exact' | 'voted' | 'miss'
}

interface Room {
  code: string
  mode: 'free' | 'theme'
  themeId: string | null       // 主题模式开局抽取，重赛重抽
  themeName: string | null
  maxRounds: number            // 4..20
  writeSeconds: 15 | 30 | 45 | 60
  prepareSeconds: 15 | 30 | 45 | 60
  banRepeat: boolean
  phase: Phase
  round: number
  phaseDeadline?: number
  prepareGraceDeadline?: number       // 掉线加时的截止点
  hostUid: string
  players: Player[]
  history: RoundRecord[]
  currentRecord: RoundRecord | null
  dropped: boolean             // 崩局丢弃：结算照常走完但不入库
  outcome?: 'exact' | 'voted' | 'none' | 'break' | 'interrupted'
  matchId?: string
  startedAt?: number
  endedAt?: number
  matchPlayers?: { uid: string; name: string; seat: number }[]   // 开局成员快照
  resultPlayers?: { uid: string; name: string; seat: number }[]  // 结算成员快照
  persisted?: boolean          // 保证同一局只入库一次
  rematchEligibleUids?: string[]
  rematchVotes?: Record<string, 'rematch' | 'room'>
  rematchDeadline?: number
  createdAt: number
  lastActiveAt: number
}
```

- `Phase` 比设计稿多一个 `interrupted`：游玩中只剩 1 人时本局中断，清空词路径、不入库，只保留「回房间／回主页」两个出口。
- `themeId` / `themeName`：只在主题模式且本局已开始时非空；回大厅、切到自由模式、重赛分流回等待页时清空。
- `Player.disconnectedAt` / `leftReason`：断线时标记，`leftReason: 'disconnect'` 同时用于 90 秒保席与准备加时判断；主动退出直接移除席位，不留字段。
- `Room.matchPlayers`：开局参与者 UID、姓名与席位快照，历史记录不随离线席位清理而消失；`resultPlayers` 是结算时的成员快照。
- `Room.rematchEligibleUids` / `rematchVotes` / `rematchDeadline`：结算后 30 秒窗口的有效玩家、选择与截止时间；有人投票后 `phase` 由 `result` 变为 `rematch`。
- `Room.persisted` / `Room.dropped`：前者保证幂等入库，后者让崩局对局走完结算页但跳过写入。
- 房间 5 分钟无活动即销毁（按 `lastActiveAt` 计算），快照额外下发 `idleDeadline` 供前端显示空闲倒计时。

### 8.2 SQLite

```sql
CREATE TABLE players (
  uid TEXT PRIMARY KEY, name TEXT NOT NULL,
  created_at INTEGER NOT NULL, last_seen INTEGER NOT NULL
);

CREATE TABLE name_history (
  uid TEXT NOT NULL, name TEXT NOT NULL, changed_at INTEGER NOT NULL
);

CREATE TABLE matches (
  id TEXT PRIMARY KEY, room_code TEXT NOT NULL,
  mode TEXT NOT NULL, theme_id TEXT,
  max_rounds INTEGER NOT NULL, total_rounds INTEGER NOT NULL,
  converged_round INTEGER,
  outcome TEXT NOT NULL,              -- exact | voted | none
  started_at INTEGER NOT NULL, ended_at INTEGER NOT NULL

CREATE TABLE match_players (
  match_id TEXT NOT NULL, uid TEXT NOT NULL, seat INTEGER NOT NULL,

);

CREATE TABLE match_rounds (
  match_id TEXT NOT NULL, n INTEGER NOT NULL,
  words_json TEXT NOT NULL, marks_json TEXT NOT NULL,
  votes_json TEXT, outcome TEXT NOT NULL,

);

CREATE INDEX idx_mp_uid     ON match_players(uid);
CREATE INDEX idx_match_time ON matches(started_at DESC);
```

**两条硬边界**

1. 房间状态只在内存，5 分钟无活动即销毁，永不落库
2. 只有走完结算页的对局才入库；崩局（`dropped`）与中断（`interrupted`）的对局一个字不留

## 九、协议

**客户端 → 服务端**

| 消息 | 载荷 | 说明 |
|---|---|---|
| `hello` | `{ uid?, roomCode?, leaveRoom? }` | 握手恢复身份；`leaveRoom:true` 优先完成主动退出，不先恢复参与资格 |
| `createRoom` | `{ mode, maxRounds, writeSeconds, prepareSeconds, banRepeat }` | 忽略客户端传来的 `themeId`／`themeName`，主题只由服务端抽取 |
| `joinRoom` | `{ code }` | 房号自动转大写并兼容全角数字；仅 lobby 可加入 |
| `updateSettings` | 同 `createRoom` 字段 | 仅房主，仅 lobby；会清空已抽取的主题 |
| `rename` | `{ name }` | 1–12 字；不在房间时也可改，写 `players` 与 `name_history` |
| `openProfile` | `{ page?, filter? }` | 只读档案，回 `profile`；`filter` 为 `{ type: 'any', value, from?, to? }`，一段输入同时匹配房号前缀、UID 前缀、名字、主题与时间，命中项随每条对局以 `hits` 返回；不广播、不占用写操作限流 |
| `resetIdentity` | `{}` | 生成新 uid 与默认名；旧数据保留；在房间内先按主动退出处理 |
| `transferHost` | `{ uid }` | 仅房主，仅 lobby，目标须在线；双方准备状态重置 |
| `setReady` | `{ ready }` | 大厅内随时可切换，没有冷却；房主无需准备 |
| `start` | `{}` | 仅房主；2–4 人，非房主全员已准备且在线 |
| `typing` | `{ word }` | 写词阶段输入态上报，300ms 限流；`draft { text }` 为兼容别名 |
| `submitWord` | `{ word }` | 服务端做字符、长度与重复词校验；失败不消耗本轮 |
| `vote` | `{ yes }` | 5 秒投票；`submitVote { agree }` 为兼容别名 |
| `breakVote` | `{ yes }` | 崩局投票，提交后不可更改 |
| `ready` | `{ ready? }` | 准备阶段快速准备，缺省 `true` |
| `rematch` | `{ choice: 'rematch' \| 'room' }` | 兼容旧 `accept`；`interrupted` 阶段只接受 `room` |
| `leave` | `{}` | 主动退出，立即移除席位 |

协议约束：`toast` 事件携带事件类型、操作者 UID 和展示名；主动退出、掉线、重连、到期分别使用 `leave` / `disconnect` / `return` / `expired`。玩家快照提供 `connectionState`、`disconnectedAt`、`reconnectDeadline`。`hello` 的恢复结果以实际成功为准，恢复失败不会自动重新加入旧房间。

**服务端 → 客户端**：`state`（全量快照）、`hello`（握手结果）、`profile`（档案）、`identity`（新身份）、`error`、`toast`

- 快照对他人隐藏 `submittedWord` / `vote` / `breakVote` / `draft`，只暴露 `typing` / `submitted` / `voted` / `breakVoted` 布尔状态；写词阶段不下发 `words` / `marks` / `votes`
- 写操作限流：每 uid 每 500ms 一条；`typing` / `draft` 单独 300ms
- 档案只发给请求方：`profile` 不进房间广播、不刷新房间活动时间；`openProfile` 不受写操作限流影响
- 心跳 30 秒（服务端 ping，未回 pong 即断开），90 秒内可用原 uid 重连恢复席位
- 房主退出或掉线过期时，权限移交给最早加入且在线者；同一 uid 被另一页面接管时，旧连接收到错误并停止自动重连

## 十、前端与设计系统

原生 JS，无框架。本章是页面视觉与交互规范的统一入口；产品定位和原则见 `Agents/PRODUCT.md`，实现令牌及响应式规则位于 `public/styles.css`。新增或改版页面应复用本章规范；调整公共令牌、断点或页面结构时同步更新此处，避免各页面另写一套规则。**图标一律用图标库，不手写 SVG 图标路径。**

### 10.1 依赖

| 用途 | 方案 |
|---|---|
| 图标 | **Lucide**（`lucide-static`），构建期抽成一张本地 sprite，运行时不请求 CDN |

### 10.2 设计令牌与视觉语言

使用现有 CSS 变量，不为同一种用途另造颜色、圆角或动效。当前主题为浅色，背景氛围沿用已有实现，不在新面板中叠加装饰性渐变、玻璃效果或状态灯。

| 角色 | 令牌 / 当前值 |
|---|---|
| 页面底色 / 面板 / 悬停面板 | `--bg: #F4F5F9` / `--card: #FFFFFF` / `--card-hover: #F8F9FC` |
| 边框 / 强边框 | `--line: #E1E4EC` / `--line-strong: #C9CFDC` |
| 正文 / 次要文字 / 辅助文字 | `--ink: #16161A` / `--ink-secondary: #505565` / `--muted: #666C7E` |
| 主操作 / 悬停 / 浅背景 | `--accent: #3D5AFE` / `--accent-hover: #2C47EA` / `--accent-soft: #EEF1FF` |
| 警示 / 成功 | `--vermilion: #FF5A46` / `--jade: #0E9F6E`，配套浅色背景令牌 |
| 玩家席位 0–3 | `#3D5AFE` / `#FF5A46` / `#00A878` / `#9B6BFF`，词卡沿用同一席位配色 |
| 大 / 中 / 小圆角 | `--radius-lg: 16px` / `--radius-md: 12px` / `--radius-sm: 9px` |
| 动效时长 | `--dur-1: 120ms` / `--dur-2: 180ms` / `--dur-3: 240ms` / `--dur-4: 320ms` |
| 缓动 | `--ease-out: cubic-bezier(.16,1,.3,1)`；`--ease-in-out: cubic-bezier(.4,0,.2,1)`；`--ease-snappy: cubic-bezier(.22,1,.36,1)` |

- 系统无衬线字体：`system-ui, -apple-system, "PingFang SC", "Source Han Sans SC", "Microsoft YaHei", sans-serif`；基础字号 16px、行高 1.5。
- 通用页面标题 32px/650，区块标题 15px/600；具体页面按信息密度适当缩小（档案姓名 22px、历史详情标题 26px），不要把所有文字都做成标题或评级。
- 主要正文通常 14–16px，辅助信息 12–13px；通过字重、位置、分组和留白建立层级，不靠低对比度隐藏内容。
- 面板复用 `.surface-block`：白底、1px 描边、16px 圆角，常规内边距 18px 20px。优先使用分隔线组织列表，避免层层嵌套卡片。

### 10.3 组件、状态与动效

交互组件按适用情形提供 default / hover / active / focus-visible / disabled，以及加载、成功或错误反馈；静态内容不伪装成可点击控件。优先复用 `.button`、`.icon-button`、`.input`、`.surface-block` 等既有组件。

| 组件 | 规范 |
|---|---|
| 全局顶栏 | 顶栏固定于视口顶部，使用不透明圆角底板；1200px 及以上各页面顶栏居中并统一为 `min(100vw, 1184px)`，中间展示源码、隐私政策和 Q&A 入口；Q&A 暂未开放，页脚同样提供预留按钮；弹窗与 Toast 保持在顶栏之上，锚点定位避开顶栏 |
| 按钮 | 主操作用 primary，次要操作用 secondary，危险操作明确区分；常规按钮最小高度 50px、内边距 12px 20px。显式声明 `type`，提交表单用 submit，其余用 button |
| 链接 / 可点击条目 | 导航使用真实 `a` 和有效 href，支持键盘、新标签页、刷新和后退；整条记录可点击时不得嵌套其他交互控件 |
| 输入框 / 搜索 | 可见 label，不只靠 placeholder 表达用途；按类型使用 search、date 等原生输入；切换类型同步更换输入控件和校验；错误说明应给出恢复方式 |
| 选择控件 | 开关、步进器、分段选择沿用现有组件；普通搜索类型优先用原生 select，不为了统一动画重写原生下拉 |
| 弹窗 | 用于必要的确认或短任务；独立内容使用页面，不把历史详情塞进弹窗。危险操作二次确认，关闭后恢复合理焦点 |
| 折叠内容 | 使用原生 details/summary 按需展开投票等次要信息，保证键盘可操作 |
| 滚动区 | 复用项目滚动条方案；页面自然滚动，长列表不新增无必要的嵌套滚动区 |
| Toast | 用于短暂旁路反馈，沿用顶部进入、约 2.5 秒退出；不能作为关键错误和恢复操作的唯一载体 |

- 常规悬停与按压反馈使用 120–180ms，页面或内容切换使用 240–320ms；优先用可中断的 transition。页面入场等已有 keyframes 可保留，不要求所有内容都加进出动画。
- 状态变化动效服务于反馈，避免回弹、逐区块无意义入场和长时间阻塞操作；列表或词卡更新保持阅读位置与输入焦点。
- 必须尊重 `prefers-reduced-motion`，停用或简化位移、循环背景和入场动效；动画不能成为内容可见的前提。
- focus-visible 使用清晰描边；状态和玩家身份不能只靠颜色表达。普通文字对比度目标至少 4.5:1，大字至少 3:1。

### 10.4 信息层级与排版

- 先确定玩家当前任务和查找依据，再决定内容顺序与面积；同屏优先突出一项主要任务，不让所有字段拥有相同权重。
- 标题表达页面用途，仅在解释规则、限制或操作后果时添加说明；不机械地给每个标题配副标题，不添加无意义状态灯。
- 不同类别的信息通过独立行、区域、标签和留白分组，不能把房号、模式、玩家、结果等一律用 `·` 串成一行。
- 使用 8px 为主的间距节奏，常用区块间距 16px / 24px；允许根据条目内容增加高度，不能为保持等高牺牲可读性。
- 长昵称、主题和 UID 应允许合理换行；数字日期采用等宽数字帮助扫读。中文标签不拆成逐字竖排，不截断关键结果。
- 全站不使用 emoji 图标，图标来自 Lucide；装饰图标不重复制造可访问名称，纯图标操作必须有 aria-label。

### 10.5 宽窄屏与响应式布局

以窄屏为基础、宽屏再分配空间，断点按 CSS 视口宽度而非设备型号判断。不要单纯放大字体或把单列拉宽作为宽屏适配。

| 范围 | 布局规范 |
|---|---|
| 小于 1000px | 功能页保持单列；通用 `.app` 基础宽度为 `min(100% - 40px, 600px)`，保留现有移动端边距覆盖；最低支持 320px，不产生页面级横向滚动 |
| 1000px 及以上 | 大厅、游玩、结算、档案、历史详情使用 `min(100% - 64px, 1120px)`；居中显示，不无限拉伸 |
| 通用双列 | 使用 `minmax(0, 1.15fr) minmax(0, 1fr)`，列间距 24px，区块间距 16px 或 24px，顶部对齐 |
| 小屏细化 | 480px / 380px 等断点仅解决控件换行、玩家列表和日期排布；不改变信息语义、数据或操作能力 |

- 顶栏固定在视口顶部，宽度统一由内容宽度推导：小于 1200px 时为 `calc(var(--app-w) + 32px)`，1200px 及以上统一为 `min(100vw, 1184px)`；各页面不再单独指定顶栏宽度。首页内容改在顶栏下边界以下的滚动层内滚动，该滚动层铺满整个视口宽度（整屏任意位置都可滚动），内容与页脚用 `--app-w` 居中，越界内容由滚动层原生裁切，竖向滚动条绘制在视口左侧；其他页面保持整页滚动，滚过顶栏的部分按滚动位置用 `--stage-top-clip` 裁掉。弹窗打开时锁定当前滚动层。
- 首页在 1200px 及以上采用等宽双列：左侧玩法介绍在内容容器内滚动；右侧入口收起时顶部位于视口高度 25% 处，展开设置时上移至 20%（至少避开顶栏），底部不超过视口高度 90%，空间不足时只滚动设置项；隐藏「了解玩法」链接。窄屏保留原有单列顺序与链接。隐私阅读页在 1000px 及以上改为两列：返回、标题与说明、目录横跨两列，正文按「身份」「记录」与「保存与删除」「部署」分两列独立堆叠，页面宽度随功能区一起放到 `min(100% - 64px, 1120px)`；窄屏仍是单列原顺序。
- 多块内容在两列分别堆叠时，使用独立列容器，避免左侧长内容把右侧区块撑出大段空白；窄屏下容器恢复纵向排列，DOM 阅读和键盘顺序保持合理。
- Grid 列使用 `minmax(0, …)`，子项设置 `min-width: 0`；输入框和长文本可收缩、换行，不能依赖隐藏页面 overflow 掩盖溢出。
- 返回链接、页面概览和必要的加载/错误提示可横跨两列；空态不留下无意义的第二列占位。
- 搜索框与主要操作不被挤出屏幕；窄屏保留可见标签。历史搜索没有按钮，时间是输入框内的右侧徽标，不能遮挡输入内容。

### 10.6 各页面布局约定

| 页面 | 窄屏信息顺序 | 宽屏分区 |
|---|---|---|
| 大厅 | 房间与玩家信息、设置、操作 | 左侧房间与玩家，右侧设置与操作；两列独立排列 |
| 游玩 | 当前阶段、词语、输入/投票/准备、玩家状态及退出 | 左侧阶段与玩家状态，右侧词语和操作；沿用 `.game-info` / `.game-controls` |
| 实时结算 | 结果、下一步、导出海报、词路径、投票 | 结果横跨两列；左侧导出海报与词路径，右侧下一步与投票；中断页仅保留其有效操作 |
| 个人档案 | 身份、对局记录与搜索、隐私、身份操作 | 左侧身份/隐私/操作，右侧记录；列比例 `0.65fr / 1.35fr`，优先给记录与搜索分配空间 |
| 隐私说明 | 返回、标题与说明、目录、身份、记录、保存与删除、部署环境、返回 | 返回、标题与目录横跨两列；左侧身份与记录，右侧保存与删除与部署环境，通用双列比例 `1.15fr / 1fr` |
| 历史详情 | 返回、结果概览、同局玩家、词路径、投票 | 返回和概览横跨两列；左侧词路径，右侧同局玩家与投票，独立列比例 `1.15fr / 1fr` |

**导出海报**

- 固定 540 宽、按 2 倍导出；顺序为品牌标识、结论与对局信息、完整词过程、脚注品牌。
- 结论与说明复用结算页文案；人数、轮次与模式（或主题）收在标题区下方的一行 meta 里，不单独占卡片；词过程直接使用结算页的思考路径组件；背景沿用结算场景的氛围层。
- 不出现房号，也不放操作控件；版式按固定宽度独立排版，不受当前视口影响。

**对局记录**

- 每条记录排成两行，行距略宽于原来的三行分区。首行是关键识别信息：叠放的其余参与者头像（剔除自己，最多 3 个、其余显示 +N，左侧头像在上层、相邻重叠 12px）加全部其余参与者的名字，名字在主行内不换行、超出宽度时末尾省略号截断；日期置于右侧。头像图片本身只用底色与首字、不描边，叠放时用 2px 与面板同色的描边把相邻头像分开（悬停时跟随悬停底色）。
- 第二行的三段复用既有组件：相遇结果（带对应颜色的图标）、房号（`room-code-display`，图标 + 「房号」+ 数字）、主题（标签图标，宽屏左内缩 12px）；宽度按内容收紧，宽屏用 `120px / 96px / 剩余` 的固定轨道，保证「打满 12 轮未相遇」与高亮后的「房号 12345」都完整显示，条目之间纵向对齐；自由模式不渲染主题列；窄屏下主题标签同样保持在同行展示，不折到下一行。
- 日期按时间距离显示：一周内为相对时间（刚刚 / N 分钟前 / N 小时前 / N 天前），超过一周显示 `月/日 时:分`，超过一年只显示 `年/月/日`；字号 14px。
- 整条是详情链接，「查看详情」贴在条目右下角，小于 561px 不显示该提示；悬停底色比文字栏左右各外扩 12px。
- 搜索是单个输入框，输入即搜（约 240ms 防抖，不跳转页面，用 `replaceState` 更新 `?me&q=` 后重取第一页）。一段输入同时参与所有维度：房号前缀、参与者 UID 前缀、参与者名字（包含）、主题名（包含），能解析成日期时再叠加时间范围（`2026-01-01`／`2026/1/1`／`20260101`／`2026年1月1日`／`2026-01`／`2026`，以及 `~`、`至`、`到` 连接的区间）。任一维度命中即算搜到，不做「先分类再排除」，记不全房号或 UID 也能搜；时间范围作为同一组 OR 条件，与其他维度并列。没有搜索／清除按钮，也没有输入框下方的说明文字；只有输入能解析成时间时，才在输入框内部靠右显示「按 2026/01 匹配」。只查询本人参与过的对局。
- 结果条目高亮真正命中的那几处：房号命中高亮房号、UID 前缀命中高亮那个人的名字、名字命中高亮名字里的片段、主题命中高亮主题名、时间命中高亮该条日期；一条记录可以同时命中多个维度，则多处一起高亮。
- 每页 10 条，条件（`?me&q=`）与页码保存在地址中，刷新、后退、详情返回均应恢复；清空输入框即回到全部记录。输入框占满整行，时间徽标绝对定位在框内右侧，出现时输入框右侧留出对应内边距，长区间在框内尾部省略并以 `title` 给出完整区间。
- 区分尚无对局、搜索无匹配、读取中和请求失败；失败必须有可恢复入口，不能一直停留在加载文案。

**历史详情**

- 使用独立地址 `?me&match=<id>`，可携带原搜索条件和页码；参考结算的信息类型，不照搬实时操作区。
- 展示结果、房号、模式/主题、起止时间、轮次、当时玩家昵称及 UID、完整词路径和逐轮投票。无权限与记录不存在使用统一提示。
- 不显示重赛、准备、房间退出或实时倒计时；投票明细默认折叠，原始词语和未提交/非法标记保留。

### 10.7 页面变更验收

- 至少覆盖 390px 窄屏、1000px 附近断点、1440px 宽屏；以浏览器实际视口和计算样式验证，检查页面级横向溢出、列对齐、按钮可达及长内容换行。
- 使用长昵称、四人局、长词路径和日期范围检查布局；覆盖空数据、加载、失败、无匹配、分页首尾及无权详情。
- 检查键盘焦点、真实链接、表单标签、折叠操作及减少动态效果；搜索与详情还需验证刷新、前进/后退和条件恢复。
- 结构测试与相关 UI 回归通过后，再做浏览器布局检查；不能把字符串测试当作视觉验收。受工具限制未验证的视口或交互需在交付时明确说明。

## 十一、身份

- **uid**：8 位数字+大写字母随机串（字符集去掉 `0/O/1/I/L`），存 `localStorage` + cookie `sy_uid`（30 天）
- **首访**：服务端分配 LocalSend 风格名字，写入 `players`
- **改名**：改 `players.name` 并追加 `name_history`；uid 不变，档案连续；房间内改名即时同步给其他人
- **邀请链接**：`/?r=CODE`，打开即进房；不再携带或记录邀请人
- **隐私**：档案页底部一句话说明只存了 uid、名字与完成过的对局
- **档案与历史详情**：档案入口为首页头像，地址 `/?me`；展示身份、曾用名和本人参与的对局，每页 10 条。支持房号 / UID / 日期范围搜索和独立详情链接；信息层级、页面布局、响应式与恢复行为统一见 §10.6，不在本节重复维护 UI 规则。
- **我是新人**：二次确认后服务端生成新 uid 与随机名；旧 `players`、`name_history` 与对局记录保留在库里但不再关联新身份；在房间内触发按主动退出处理，他人收到退出提示

> 当前实现：以上规则均已落地（M6）。档案走独立 `openProfile` / `profile` 消息，不进房间广播、不占用写操作限流；`resetIdentity` 先回 `identity`，再补发一次无房间的 `state`。

## 十二、部署

单进程：静态文件 + WS 同端口；数据库默认 `data/synconym.db`（better-sqlite3），部署时用 `DB_PATH` 指向持久卷上的文件，不要把卷挂到整个 `data/`，否则会盖住随代码发布的 `themes.json`；环境变量 `PORT`、`PUBLIC_URL`、`DB_PATH`；反向代理需转发 `/ws` 的 Upgrade 头；无外部 API 依赖。

## 十六、已确认的决定

以下为 v0.5 定稿时确认的规则，不再列为待议：

1. **2 人局崩局投票**：≥ 半数即通过，2 人局 1 票即崩
2. **打满轮次未相遇**：记录保留；崩局与中断的对局不入库
3. **结算分流**：结算即开始 30 秒；退出即时移除，断线等到截止；到期剔除未选/仍离线者，剩余至少 2 人全选重赛直接开局，否则回等待页，无人留下才关房间
4. **崩局投票未过半**：直接进下一轮，不再走准备
5. **字母大小写**：`iOS` 与 `ios` 归一为同一词

### 17.5 代码约定

- 服务端是唯一权威，客户端不发号施令、只渲染快照
- 所有时间点用毫秒时间戳，倒计时以服务端 `phaseDeadline` 为准，客户端只做插值显示
- 归一化、校验、判定集中在 `rules.js`，前后端共用同一份规则（前端用于即时拦截，服务端用于最终裁决）
- 每次状态变更后立即广播全量 `state` 快照；客户端可就地 patch 局部节点（避免重建写词输入框、丢失焦点与输入法状态），但数据来源始终是全量快照
- 提交前跑 `npm test`；每个里程碑完成即 `git commit`

# Synconym 创新游戏模式设计规范

本文档为《近意词 Synconym》规划并定义五种全新衍生游戏模式：**Shiritori（接龙）**、**Livonym（即时竞猜）**、**Impostor（思维卧底）**、**Blitz（极速闪电）**与 **Bridge（语义搭桥）**。

设计严格遵循 Synconym 的核心理念：界面克制、交互直观、纯文字思维碰撞、轻量高质感。

---

## 模式概览矩阵

| 模式名称 | 英文标识 | 支持人数 | 核心机制 | 判定/胜负条件 |
| :--- | :--- | :--- | :--- | :--- |
| **接龙** | **Shiritori** | 2–4 人 | 抽取上轮尾字作为公共首字约束输入 | 在满足公共首字约束下达成全员相遇 |
| **即时竞猜** | **Livonym** | 3–8 人 | 一人实时打字描述，其余人看流式文本抢猜 | 按抢猜成功顺序阶梯计分，多轮累计总分排名 |
| **思维卧底** | **Impostor** | 3–6 人 | 暗藏卧底故意偏离/阻碍，投票公开记名 | 最终指认卧底或卧底成功潜伏至终局 |
| **极速闪电** | **Blitz** | 2 人 | 8s 输入 + 3s 公示自动下一轮，零多余点击 | 追求在最少轮次与极限时间下达成字面完全一致 |
| **语义搭桥** | **Bridge** | 2–4 人 | 系统开局下发两极起点词，强制思维收敛 | 规定轮次内从迥异起点成功汇聚至同一词 |

## 一、 接龙模式（Shiritori）

> **“戴着枷锁起舞”** —— 既要往彼此的语义靠拢，又必须以指定的公共字起头。

### 1.1 人数与基础规则
* **人数限制**：**2–4 人**。
* **第一轮**：自由写词（可选择是否由房主/系统提供首轮起步词）。
* **后续轮次（公共首字生成）**：
  * 每轮揭晓时，系统从**本轮所有合法提交词的末尾字（末尾字符）**中，随机抽取一个字，作为下一轮全员必须遵守的**「公共首字约束」**。
  * 提取策略：仅提取汉字或字母数字；多音字以当前词的标准普通话拼音为准。

### 1.2 约束强度选项（房间设置）
在创建房间或大厅设置中提供两种模式切换：
1. **严格同字（Exact Character）**：
   * 下一轮所有玩家提交的词，**首字必须完全是该抽取字**。
   * *示例*：上轮抽中「光」，下轮全员必须以「光」开头（如「光明」、「光速」）。
2. **同音/拼音约束（Pinyin / Homophone）**：
   * 下一轮所有玩家提交的词，**首字的发音（拼音声母+韵母，不区分声调）相同即可**，降低罕见尾字导致的卡词死局。
   * *示例*：上轮抽中「绿（lù/lǜ）」，下轮以 `lu` 开头的字均可（如「路灯」、「录像」）。

### 1.3 输入框与交互规范
* **前置固定前缀（Input Affix）**：
  * 输入框最左侧呈现一个不可删除的「前置约束标签」：
    * 严格模式下展示：`[ 约束字: 光 ]`，光标紧随其后；
    * 拼音模式下展示：`[ 首音: guāng ]`。
* **实时校验与拦截**：
  * 玩家只需在框内键入剩余文字（严格模式下首字自动填入或打出必须匹配）；
  * 若前端输入不匹配约束，输入框产生微幅横向晃动（shake feedback），提交按钮禁用；
  * 超时提交时，若首字不合规，判定为 `[非法答案]`。

### 1.4 判定与胜利
* 全员在满足首字约束的条件下，写出完全相同的词（或全票投票通过为同一概念）即为相遇获胜；
* 达到轮次上限未达成则对局结束。

## 二、 即时竞猜模式（Livonym）

> **“打字机前的读心术”** —— 摒弃提交按钮，打字即直播；一人键盘飞舞，全员眼疾手快。

### 2.1 人数与赛制结构
* **人数限制**：**3–8 人**。
* **轮替机制（Round Robin）**：
  * 一局包含若干轮（等于玩家总人数，或人数 × 2 轮），每位玩家轮流担任一次**「打字员（Describer）」**，其余玩家为**「竞猜者（Guessers）」**。

### 2.2 打字与流式展现（无需提交，即打即显）
* **秘密词下发**：
  * 系统私密下发一个秘密目标词给打字员（如「高压锅」）。
* **输入框放宽与流式广播**：
  * 打字员的输入框放宽字符限制，打字员不可直接打出秘密词本身（输入命中谜底时前端提示“包含谜底不可输入”）；
  * **完全取消提交动作**：打字员键入的每一个字符，通过 WebSocket 极短节流（50–100ms）实时同步至所有竞猜者的屏幕中；
  * 竞猜者屏幕中央展示一个宛如终端/打字机效果的动态文字区，字句实时浮现、修改、删除，真实反映打字员的思考与描述轨迹。

### 2.3 竞猜与阶梯抢答积分
* **限时机制**：单轮出题倒计时 **45 秒**。
* **抢猜输入框**：
  * 竞猜者下方有专属的抢猜输入框，打字回车即猜；猜错有 1.5 秒防刷屏冷却，且猜错文本不打扰他人，仅自己可见错误动效。
* **阶梯积分算法**：
  * **第 1 位猜中者**：获得 **3 分**；
  * **第 2 位猜中者**：获得 **2 分**；
  * **后续所有在限时内猜中者**：各得 **1 分**；
  * **打字员得分**：根据猜中人数获得反馈分（至少 1 人猜中得 2 分，全员猜中额外奖励 1 分；若全员无人猜中打字员得 0 分）。
* **轮次结束**：
  * 限时用尽，或所有竞猜者均猜中时，立即结算本轮得分看板，3 秒后切换下一位打字员。

### 2.4 终局结算
* 所有人轮替完毕后，展示总排行榜：包含「冠军竞猜王」、「灵魂速记打字员」以及单轮最快反应时间（如“0.8秒神猜”）。

## 三、 思维卧底模式（Impostor）

> **“全员记名的狼人杀”** —— 谁在看似靠近，实则把大家带进沟里？

### 3.1 人数与阵营分配
* **人数限制**：**3–6 人**。
* **身份配比**：
  * **3–5 人局**：**1 名卧底（Impostor）**，其余为平民；
  * **6 人局**：**2 名卧底（Impostor）**，其余为平民。
* **身份下发**：开局暗中下发，卧底屏幕边缘有微弱暗红色呼吸光晕与专属提示词，平民完全未知。

### 3.2 对局目标
* **平民目标**：合力达成语义相遇，并在终局通过投票成功揪出所有卧底。
* **卧底目标**：
  1. 隐蔽地写出看似沾边、实则将整体语义引向歧途的词；
  2. 阻止平民在规定轮次内达成真实相遇；
  3. 或者在最终指认环节逃脱嫌疑。

### 3.3 记名投票与时间延长
* **延长投票时限**：从普通模式的 5 秒延长至 **12 秒**。
* **公开记名投票（Showing Individual Choices）**：
  * 揭晓所有人的词后进入投票；
  * 倒计时结束后，不再仅显示“通过/未通过”，而是**直观展现每一个玩家头像旁挂出的具体选择徽章（「是」或「否」）**；
  * 玩家可以复盘：*“刚才这个词明明很贴切，为什么 2 号玩家连续投了两次否？”*。

### 3.4 结算与指认环节（Accusation Phase）
* 无论因相遇提前结束，还是打满轮次上限，均进入 **30 秒抓卧底环节**：
  * 界面呈现所有存活玩家头像，玩家各自投票指认心目中的卧底；
  * 得票最多者被检举揭晓身份；
  * 若成功指认卧底，平民阵营大胜；若指认错误或票数平局，卧底阵营获胜。

## 四、 极速闪电模式（Blitz）

> **“纯粹的心灵感应，手起刀落”** —— 杜绝一切停顿，8 秒输入，3 秒对视，撞上即赢。

### 4.1 人数与节奏
* **人数限制**：**固定 2 人**（极致的一对一默契对决）。
* **快节奏时间轴**：
  * **写词阶段**：**8 秒** 极速倒计时（只够敲击键盘，容不得犹豫）；
  * **公示阶段**：**3 秒** 自动揭晓双方答案；
  * **无缝衔接**：公示 3 秒后**自动滚入下一轮写词**，完全无需点击“准备”或等待房主开始。

### 4.2 零操作交互设计
* 整个游戏生命周期中，用户**除了打字敲键盘之外，不需要点击页面上的任何按钮**。
* 移除回合间的人工投票环节：
  * 核心目标定为**「追求字面完全一致（Normalized Exact Match）」**；
  * 只要服务端检测到文本归一化后一致（繁简同化、大小写与空格忽略后相同），立即瞬间爆发胜利动画，冻结计时器。

### 4.3 终局评价标准
* 结算海报与成绩记录以**「总通关用时」**和**「消耗轮数」**为唯二核心勋章：
  * *S级*：3 轮以内且总耗时 < 30 秒达成相遇；
  * *A级*：5 轮以内达成相遇；
  * 若打满 12 轮未相遇，直接判定极速断电。

## 五、 语义搭桥模式（Bridge）

> **“从南极走向北极”** —— 两个互不相干的极端起点，走出一条不可思议的会师之路。

### 5.1 人数与起始设定
* **人数限制**：**2–4 人**。
* **系统下发对立起点词（Round 0 起点）**：
  * 第 1 轮开始前，系统从预置的“高语义距离词库”中随机挑选并为玩家下发**毫无直接关联的初始词**；
  * **2 人局**：玩家 A 获得词甲（如「仙人掌」），玩家 B 获得词乙（如「空间站」）；
  * **3–4 人局**：每位玩家分别获得一个处于不同维度的初始词（如「火锅」、「极光」、「微积分」）。

### 5.2 推进与搭桥逻辑
* **第 1 轮写词**：
  * 玩家必须看着自己的起始词和对方的起始词，写出一个尝试向彼此“架桥”的中间词；
* **后续轮次**：
  * 沿用 Synconym 经典规则，基于上一轮大家公开的词继续聚拢；
* **胜利条件**：
  * 在规定轮次（默认 10 轮）内，全员最终写出同一个词或全票通过判定为同一事物。

### 5.3 结算亮点：思维搭桥海报
* 结算时生成的路线图具有极强的传播性与成就感：
  * 左侧展示「起点 A」，右侧展示「起点 B」；
  * 中间清晰绘制一条波折但最终相交的节点链条，记录双方如何打破认知鸿沟、实现逻辑闭环的完整推演轨迹。

## 六、 协议与数据结构拓展建议

为支持上述新模式，在原有房间与消息协议基础上做以下最小字段增量：

### 6.1 房间模式枚举（Room Settings）
```json
{
  "mode": "classic" | "shiritori" | "livonym" | "impostor" | "blitz" | "bridge",
  "shiritoriConstraint": "exact" | "pinyin",  // 接龙约束模式
  "blitzWritingSec": 8,                       // 闪电模式输入时限
  "blitzRevealSec": 3                         // 闪电模式展示时限
}
```

### 6.2 扩展广播消息（WebSocket Payload）
* **接龙模式（`shiritori_rule`）**：
  ```json
  { "type": "shiritori_rule", "requiredChar": "光", "requiredPinyin": "guang" }
  ```
* **即时竞猜模式流式同步（`livonym_stream`）**：
  ```json
  { "type": "livonym_stream", "describerUid": "UID_01", "text": "一种圆圆的、爆开的..." }
  ```
* **思维卧底公开投票（`vote_result_detailed`）**：
  ```json
  {
    "type": "vote_result_detailed",
    "votes": [
      { "uid": "UID_01", "choice": "yes" },
      { "uid": "UID_02", "choice": "no" }
    ],
    "passed": false
  }
  ```
* **搭桥起点下发（`bridge_start`）**：
  ```json
  {
    "type": "bridge_start",
    "startingWords": {
      "UID_01": "沙漠",
      "UID_02": "潜水艇"
    }
  }
  ```
